# PTDex

PTDex is an EverQuest database website, a fork of EQDB, for EQEmu servers: search and browse items, spells,
NPCs, zones, tradeskills, factions, pets and AAs straight from an EQEmu (PEQ-schema)
game database, plus player-facing pages built on the same data.

## Credits

Original project: **EQDB** by **Convection**: <https://github.com/mifisher324/eqdb>.
EQDB's search engine, item/spell/NPC/zone pages, the API, weight sets and the
identification tooling are Convection's work.

This tree is a server's fork of EQDB. It adds:

- **Build simulator**: theorycraft a multiclass build (classes, AAs, gear).
- **AA browser**: AA search and detail pages with tooltips.
- **Leaderboards (read pages)**: raid encounter boards, parse rankings, season standings
  and character pages, backed by a separate leaderboard database.
- **Gear score**: per-item and per-character gear scores (`gear_score.py`,
  `build_gear_scores.py`, `effect_score.py`).
- **Character and guild pages**: character browser, profiles, compare, PoP/PoT flag
  progression, guild directory with banners and achievements.
- **Community forums**: Markdown forum posts with replies and moderation (`community-wiki/`).
- **Page cache**: a shared on-disk cache for signed-out item/NPC/spell/zone pages.
- A restyled interface ("PTDex").

See `CREDITS.md` for the bundled third-party libraries.

## Local setup

You need Python 3.11+ and an EQEmu database (the public PEQ dump works). Nothing
here needs access to any particular server.

### With Docker

1. `cp configuration.ini.example configuration.ini` and set `[database]` to
   `host = db`, `port = 3306`, `user = eqdb`, `password = eqdb`, `database = peq`.
2. Download a PEQ database dump and put the `.sql` (or `.sql.gz`) file in `./db/`.
   MariaDB imports it the first time it starts. The dump is not bundled.
3. `docker compose up`, then open <http://localhost:5001>.

### Without Docker

1. `pip install -r requirements.txt`
2. `python configure.py` writes a blank `configuration.ini`; fill in `[database]`.
3. `python create_local_db.py` creates the site's own SQLite store (`local_db.db`).
   It deletes an existing one, so run it once.
4. `SITE_TYPE=Development python eqdb.py`, then open <http://localhost:5001>.

### Leaderboards

`python create_leaderboard_db.py` creates the leaderboard tables in the database
named by `[leaderboard_database] connection` (or `LEADERBOARD_DB_URL`). Point it at
the same MariaDB to get empty boards. With nothing configured a local SQLite file
is used, so the pages load with no data.

Discord login, the player count and the partner sidebar stay off while their
settings are empty.

## Deploying safely

- `site_type = Development` (the example default) is for a local machine only. In that
  mode the staff-only routes (`/wiki`, `/wiki/media`) let everyone in, OAuth runs over
  plain HTTP, session cookies are not marked Secure, and errors show tracebacks.
  Never expose a Development instance to the internet; use `Production` there.
- Set `FLASK_SECRET_KEY` (or `[flask] secret_key`). Without it a random key is made at
  every start and sign-ins do not survive a restart.
- The app trusts one reverse proxy (`ProxyFix`) and builds the Discord OAuth redirect
  URI from `X-Forwarded-Proto/Host/Prefix`. Your proxy must set or overwrite those
  headers; never pass client-supplied values through.

## Configuration reference

`configuration.ini.example` is generated by `python configure.py configuration.ini.example`.
Environment variables override the matching values (shown in brackets).

| Section | Keys | Notes |
|---|---|---|
| `[DEFAULT]` | `site_type`, `site_version`, `site_fqdn`, `debug` | `site_type`: `Development`, `Beta`, or anything else for production [`SITE_TYPE`, `SITE_VERSION`]. |
| `[triune]` | `expansion`, `expansion_rule` | Content era: fallback expansion number, and an optional `rule_values` row to read it from. |
| `[database]` | `driver`, `host`, `port`, `user`, `password`, `database` | The EQEmu game database, read-only [`DB_DRIVER`, `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_DATABASE`]. |
| `[local_database]` | `connection` | The site's own store (weights, guild page profiles, preferences). Default `sqlite:///local_db.db` [`LOCAL_DATABASE`]. |
| `[leaderboard_database]` | `connection` | SQLAlchemy URL of the leaderboard DB [`LEADERBOARD_DB_URL`]. |
| `[leaderboard]` | `staff_discord_ids`, `ingest_token` | Numeric Discord ids allowed into staff-only pages; shared secret for an ingest extension (empty = ingest refused) [`LEADERBOARD_STAFF_IDS`, `LEADERBOARD_INGEST_TOKEN`]. |
| `[forums]` | `moderator_ids` | Discord ids that may edit or delete any forum post. Empty = the staff list [`FORUM_MODERATOR_IDS`]. |
| `[path]` | `app_log`, `flask_log` | Log files. |
| `[discord]` | `client_id`, `client_secret` | Discord OAuth app for sign-in [`DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`; `DISCORD_REDIRECT_URI` in Development]. |
| `[flask]` | `secret_key` | Session key. Empty = a random key per process, so sessions reset on restart [`FLASK_SECRET_KEY`]. |
| `[site]` | `name`, `base_url`, `patcher_url`, `discord_invite`, `support_url`, `partner_feed_enabled`, `partner_feed_path` | Public values shown on pages (install guide download link, support link, ...). |
| `[loginserver]` | `api_url`, `api_token`, `cors_origin` | Login-server web API for the player count. If `api_url` or `api_token` is empty, no call is made and `/api/player-count` answers "unavailable" [`LOGIN_API_URL`, `LOGIN_API_TOKEN`, `PLAYER_COUNT_CORS_ORIGIN`]. |
| `[internal]` | `allow_ips` | Peers allowed to call `/internal/*` endpoints an extension may add. Empty = nobody. |
| `[page_cache]` | `enabled`, `dir`, `ttl`, `max_mb`, `browser_ttl` | Optional; see `page_cache.py` [`PAGE_CACHE_*`]. |

Other switches: `GEAR_CALIBRATE_ON_BOOT=0` skips rebuilding the gear-score calibration at startup.

## Optional private extensions

If a Python package named `eqdb_private` can be imported (for example a directory
`eqdb_private/` next to `eqdb.py`, which `.gitignore` excludes), `eqdb.py` calls
`eqdb_private.register(app, site_config)` after all public routes are registered.
An extension can add blueprints and routes, replace providers such as
`app.extensions['eqdb_player_count_provider']`, `routes.characters.linked_character_rows`,
`guild_portal.manageable_guilds` or `leaderboard.validate_encounter`, and set
`app.config['PRIVATE_FEATURES'] = True` so templates show links to its pages.
Without it the site runs with the public feature set.

## Game art

PTDex does not include EverQuest client art. The build simulator looks for class icons at
`static/class_icons/<class>.gif` (for example `bard.gif`, `cleric.gif`; the names are in
`routes/build_simulator.py`). Without them it shows each class's name instead.
